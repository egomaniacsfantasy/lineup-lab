## Hard-won technical facts — these cost real time, do not rediscover them

1. **`import.meta.env?.X` is never substituted by Vite `define`.** The optional
   chaining defeats textual replacement, so you get `{}` in the bundle and a
   silently dead value. This bug shipped three separate times (API base, then
   two ESPN flags). Config lives in `vite.config.ts` as `__API_BASE__`,
   `__ESPN_EXTENSION_URL__`, `__ESPN_LOGIN_ENABLED__`, `__BUILD_STAMP__`, read
   through `src/services/apiBase.ts`. There is a regression test pinning the
   literal string.

2. **A regression test that does not fail when you reintroduce the bug is
   worthless.** My first `/api` guard matched only one spelling of `fetch(`. I
   proved it vacuous by putting the bug back and watching it pass. Always
   verify a new guard by reintroducing the defect.

3. **CSS cannot hide WKWebView scroll indicators, bounce, or horizontal pan.**
   Those live on the `UIScrollView`, not in CSS. I reported this fixed twice
   from browser measurements and was wrong both times. It is now handled in
   `ios/App/App/MainViewController.swift` — `showsVerticalScrollIndicator`,
   `showsHorizontalScrollIndicator`, `alwaysBounceHorizontal`, `bounces`,
   `contentInsetAdjustmentBehavior = .never`, pinch disabled — reapplied in
   `viewDidAppear`. **Browser DevTools cannot verify iOS scroll behaviour.**

4. **`SceneDelegate` builds the window in code.** Info.plist names `Main` as
   the scene storyboard, but `SceneDelegate.swift` sets
   `window?.rootViewController` directly. Changing the storyboard's
   `customClass` is therefore inert. This was the root cause of the whole
   "EspnAuth plugin is not implemented on ios" saga — `MainViewController` was
   never instantiated, so `capacitorDidLoad` never ran and the plugin was never
   registered. Fixed by pointing `SceneDelegate` at `MainViewController()`.

5. **`packageClassList` is generated only from npm plugin packages**, by
   scanning them for `@objc(...)` (see
   `node_modules/@capacitor/cli/dist/util/iosplugin.js:53`). An app-target
   plugin class can never appear there. App-target plugins must be registered
   manually in `capacitorDidLoad()` via `registerPluginInstance`.

6. **`WKHTTPCookieStore` can read HttpOnly cookies.** The native cookie store is
   not bound by the JS rule. This is what makes native ESPN sign-in viable
   without ever handling a password.

7. CSS grid: **`min-width: auto` on grid items widens tracks.** Hit this 4+
   times. Also `auto-fit` + `minmax()` arithmetic is silent — 3x96 + 2x8 = 304 >
   299 quietly collapses to 2 columns. Also `justify-content: safe center`, not
   `center`, or content overflows in both directions and draws over the clock
   and battery.

8. `100dvh`, not `100vh`, in WKWebView. `contentInset: 'never'` in
   `capacitor.config.ts` hands safe-area handling back to CSS.

9. There **is** an Express error handler at `server/index.js:30`. I once claimed
   there wasn't because I grepped for the wrong parameter names.

10. A missing `}` in a CSS file nested a `:root` block inside a media query and
    wiped every design token on desktop (Times New Roman everywhere). There is
    now `test/cssBraceBalance.test.mjs`. Keep it passing.

## Where I left off — read this before doing anything

`ios/App/App/EspnAuthPlugin.swift` is **modified and uncommitted**. Two changes:

1. **Widened cookie matching.** It previously only matched cookies whose domain
   contained `espn.com`. ESPN actually sets `espn_s2` and `SWID` across
   `espn.com`, `go.com`, and `registerdisney.go.com` depending on which path the
   sign-in took, so domain filtering was a guess that could drop a valid
   session. It now matches by cookie name on any host.

2. **Instrumented the capture.** The plugin records cookie count, the hosts
   seen, and whether each of `espn_s2` / `SWID` was present. A cancel that
   happens *after* cookies appeared now reports those specifics instead of a
   bare "cancelled" — because a cancel after a successful sign-in is the
   interesting case: it means the cookies were there and we failed to recognise
   them.

**It compiles (`BUILD SUCCEEDED`) but has not been through the guard suite and
has never been exercised against a real ESPN login.**

The single remaining unknown in the whole ESPN feature is: **does the sheet
actually capture cookies?** Everything upstream of that is confirmed working.
